# معماری / Architecture

یک ورکر کلادفلر هم ربات را اجرا می‌کند، هم مینی‌اپ را سرو می‌کند و هم API استودیو را.

```
Telegram  ──webhook──▶  worker/worker.js
                           │  ├─ /            → html (مینی‌اپ تک‌فایل، از worker/index.js)
                           │  ├─ /telegram-web-app.js → نسخهٔ خودمیزبان بریج تلگرام
                           │  ├─ /api/*      → استودیو (POST + احراز هویت)
                           │  └─ /webhook    → آپدیت‌های ربات
                           ▼
                     Bot API 10.3  /  KV (RICHKV)
```

## ماژول‌ها

| مسیر | نقش |
| --- | --- |
| `worker/worker.js` | نقطهٔ ورود ورکر: مسیریابی، وبهوک ربات، احراز هویت، API، سهمیه |
| `worker/index.js` | خروجی بیلد: HTML مینی‌اپ + دادهٔ راهنماها (خودکار ساخته می‌شود) |
| `worker/tg-web-app-content.js` | نسخهٔ خودمیزبان `telegram-web-app.js` برای شبکه‌هایی که `telegram.org` رویشان فیلتر است |
| `miniapp/src/blocks.ts` | مدل بلوک‌ها و تولید HTML ریچ از فیلدهای ساده |
| `miniapp/src/Composer.tsx` | سازندهٔ بصری (بدون کد) |
| `miniapp/src/App.tsx` | پوستهٔ استودیو: ادیتور، پیش‌نمایش، پیش‌نویس، قالب‌ها، انتشار |
| `miniapp/src/Renderer.tsx` | رندر HTML ریچ برای پیش‌نمایش شبیه تلگرام |
| `tools/build-worker.mjs` | تزریق HTML و داده در `worker/index.js` |

## مدل احراز هویت

1. **کاربر مینی‌اپ**: `initData` تلگرام با HMAC-SHA256 و کلید `WebAppData` + توکن ربات اعتبارسنجی می‌شود؛ `auth_date` منقضی رد می‌شود.
2. **اپراتور**: هدر `Authorization: Bearer <ADMIN_KEY>` با مقایسهٔ constant-time.
3. **انتشار در کانال**: قبل از ارسال، ادمین‌بودن ربات و مجوز `can_post_messages` از خود تلگرام استعلام می‌شود.

## ذخیره‌سازی (KV = `RICHKV`)

| کلید | مقدار |
| --- | --- |
| `u:<userId>` | سهمیهٔ مصرف‌شده، دعوت‌ها، مسدودبودن |
| `bcast:<chatId>` | پیکربندی پخش کانال (برای پست‌های زمان‌بندی‌شده) |
| `s:stats` | شمارنده‌های کلی (ارسال/کانال/کاربر) |

## جریان انتشار

1. استودیو `POST /api/send` با `rich_message` می‌فرستد.
2. `validateRich` ساختار و اندازه را چک می‌کند؛ `withFooter` امضای برند را اضافه می‌کند.
3. سهمیه (برای چت غیرخصوصی) بررسی و بعد از ارسال موفق مصرف می‌شود.
4. آمار به‌روزرسانی می‌شود.
